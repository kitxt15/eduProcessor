# eduVirtualMachine

Учебная стековая виртуальная машина на C и C++. Ассемблер переводит текст программы в байткод, процессор исполняет его, а raylib показывает содержимое видеопамяти. Дизассемблер переводит байткод обратно в ассемблерный текст.

## Сборка на macOS

Понадобятся компиляторы C и C++, CMake 3.16 или новее, raylib и локальный заголовок `../eduStack/stack.h`. Каталог `eduStack` должен лежать рядом с каталогом проекта. Текущая сборка использует `PrintStack` и `StackVerify` из этого заголовка. В проверенном коммите `eduStack` (`b684494`) `stack.h` отсутствует, поэтому его нужно взять из рабочей копии стека.

Если используешь Homebrew, установи зависимости. [Формула raylib в Homebrew](https://formulae.brew.sh/formula/raylib)

```sh
brew install cmake raylib
```

Сборка из корня проекта

```sh
cmake -S . -B build -DCMAKE_PREFIX_PATH="$(brew --prefix raylib)"
cmake --build build
```

## Запуск примера

```sh
./build/assembler example.txt -o example_bytecode.bin
./build/processor example_bytecode.bin
```

Пример рисует закрашенный круг с центром `(16, 16)` и радиусом `10`. Программа перебирает клетки от `6` до `26` по обеим осям и закрашивает те, для которых `(x - 16)² + (y - 16)² ≤ 100`. В конце `MEOW` печатает `meow-meow-meow!` и ждёт символ с клавиатуры. Нажми Enter, чтобы программа дошла до `HLT` и открыла окно `Video`. Чтобы завершить процесс, закрой окно. [Исходный код примера](example.txt)

После изменений в ассемблерном тексте снова запусти `assembler`. `processor` читает готовый `.bin`.

## Дизассемблирование

```sh
./build/disassembler example_bytecode.bin
./build/assembler disasm.txt -o roundtrip.bin
cmp example_bytecode.bin roundtrip.bin
```

Дизассемблер читает `.bin` по одной записи `Command` и выбирает текст инструкции по её коду. Результат записывается в `disasm.txt` в текущем каталоге и перезаписывается при следующем запуске. Переходы выводятся с числовыми адресами инструкций, поскольку номера меток и комментарии существуют только в исходном тексте. При совпадении файлов `cmp` завершится с кодом `0`. [Код дизассемблера](disasm.c)

## Как работает ассемблер

`ReadFile` загружает исходник в один буфер. Переводы строк заменяются на `\0`, а указатели на начала строк сохраняются в массиве `Line`. Поле `Line::buffer` указывает на текст строки, а `Line::len` хранит её длину. Структура `Text` объединяет индекс строк и указатель на буфер. Ассемблер передаёт эти две части в `ReadFile` отдельно. [Чтение исходника](text.h) · [Точка входа ассемблера](asm.cpp)

После удаления комментариев, которые начинаются с `;`, функция `WriteFile` проходит по строкам дважды.

1. **Сбор меток.** При каждой распознанной инструкции счётчик адреса увеличивается на один. Строка вида `:1` сохраняет текущий адрес в `labels[1]`. У `Label` два поля — `defined` отмечает, что метка объявлена, а `address` содержит индекс инструкции. Пустые строки и метки счётчик не увеличивают.
2. **Кодирование инструкций.** `ReadOpcode` сопоставляет имя команды с числовым кодом. Затем `WriteFile` разбирает аргумент и записывает `Command` в файл. К этому моменту таблица меток заполнена, поэтому `JMP :1` и `CALL :1` могут ссылаться на метку, объявленную ниже по тексту. [Код ассемблера](asm.h)

### Формат байткода

В `.bin` последовательно записываются структуры `Command`. Каждая запись содержит три поля. [Коды операций и структура Command](commands.h)

| Поле | Тип | Что хранит |
| --- | --- | --- |
| `command` | `int` | Код операции из `enum opcodes`. |
| `arg` | `int` | Число для `PUSH`, адрес ячейки памяти или индекс инструкции для перехода. |
| `r` | `char` | Имя регистра `a`, `b` или `c` для команд с регистром. |

Код операции зависит от формы аргумента. `PUSH 7` кодируется как `PUSH_OP` с `arg = 7`, а `PUSH a` — как `PUSHR_OP` с `r = 'a'`. Для `PUSH [3072]` используется `PUSH_MEM_OP`, для `PUSH [a]` — `PUSH_MEM_REG_OP`.

Ассемблер записывает структуру целиком через `fwrite`. Формат зависит от размера полей, порядка байтов и выравнивания на платформе сборки. Адрес перехода при этом всегда означает индекс `Command` в массиве, начиная с нуля.

## Как работает процессор

`main` инициализирует `Processor`, загружает до 10 000 записей `Command` из `.bin` и передаёт массив в `StartProcessor`. Перед запуском оба стека пусты, а регистры и память заполнены нулями. [Загрузка байткода](processor.cpp) · [Реализация процессора](processor.h)

### Структуры данных

| Поле `Processor` | Назначение |
| --- | --- |
| `st_data` | Стек значений для арифметики, сравнений и обмена с регистрами и памятью. |
| `st_return` | Отдельный стек для возврата из подпрограмм. |
| `regs[3]` | Регистры `a`, `b`, `c` в таком порядке. |
| `ram[4096]` | Целочисленные ячейки памяти, включая видеопамять. |
| `VerifyProcessor` | Указатель на функцию, которая проверяет оба стека через `StackVerify`. |

Оба стека имеют тип `Stack_t`. Стек хранит выделенный буфер, указатель на данные `data`, число занятых элементов `size`, ёмкость `capacity` и описание элемента `TypeInfo`. При `DEBUG >= 1` в структуру добавляются контрольные значения по краям, при `DEBUG >= 2` добавляются хеши. `StackPush` копирует значение в позицию `size` и увеличивает размер, а `StackPop` уменьшает размер и копирует снятое значение по переданному указателю. Обычный `POP` передаёт `NULL` и отбрасывает значение.

`TypeInfo` задаёт размер элемента и функции, с которыми работает общий код стека. В этой машине `IntInfoInit` задаёт `sizeof(int)`, печать числа и проверку байтов заполнителя `0xDE`. [Настройка типа элементов стека](int_type.h)

### Цикл исполнения

В `StartProcessor` переменная `i` служит счётчиком команд. На каждой итерации процессор читает `commands[i]`, выводит состояние через `PrintState` и выбирает действие в `switch` по полю `command`. При последовательном исполнении `i` увеличивается на один.

- **Арифметика.** `SUB` снимает верхнее значение `y`, затем следующее `x` и кладёт на стек `x - y`. `ADD`, `MUL` и `DIV` используют тот же порядок операндов.
- **Регистры и память.** `POP c` сохраняет значение в регистре `c`. `POP [c]` использует содержимое `c` как адрес в `ram`. `PUSH [3072]` читает ячейку по указанному адресу.
- **Переходы.** `JMP` устанавливает `i` в `arg - 1`, чтобы после увеличения счётчика цикл продолжился с `commands[arg]`. `JA`, `JB` и `JE` сравнивают `x > y`, `x < y` и `x == y` соответственно, где `y` лежит на вершине стека. `JumpCondition` восстанавливает оба операнда после сравнения. Если программа закончила работу с этими числами, их можно снять двумя командами `POP`.
- **Подпрограммы.** `CALL` кладёт индекс самого вызова в `st_return` и переходит по заданному адресу. `RET` восстанавливает этот индекс. После увеличения счётчика выполняется команда сразу после `CALL`.
- **Остановка.** `HLT` завершает `StartProcessor`, после чего `main` освобождает оба стека и передаёт видеопамять в `render`.

## Видеопамять и пример исполнения

Ячейки `ram[3072]`–`ram[4095]` образуют экран `32 × 32`. Пиксель `(x, y)` хранится по адресу `3072 + y × 32 + x`. Функция `render` получает указатель на `ram[3072]` и читает пиксель как `pixels[y * 32 + x]`. raylib рисует ненулевые клетки красным, а нулевые оставляет на светлом фоне. [Код отрисовки](video.cpp)

Эта программа вычисляет `7 - 2` в подпрограмме и закрашивает верхнюю левую клетку.

```asm
CALL :1
POP [3072]
HLT

:1
PUSH 7
PUSH 2
SUB
RET
```

Ассемблер привязывает `:1` к инструкции с индексом `3`, поэтому первый `Command` содержит `CALL_OP` и `arg = 3`. Процессор сохраняет в стеке возврата индекс `0` и переходит к `PUSH 7`. После `SUB` в стеке данных лежит `5`. `RET` возвращает исполнение к `POP [3072]`, которая записывает `5` в видеопамять. После `HLT` raylib рисует эту клетку красным.
